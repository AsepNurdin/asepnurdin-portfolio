01 — Background & Objectives

Background

Servers are critical assets in IT infrastructure. Default OS configurations are often insecure for production environments.

  • ▹ Rising cyber threats targeting Linux infrastructure
  • ▹ Compliance requirements (CIS Benchmark, ISO 27001)
  • ▹ Default Ubuntu configuration still has many vulnerabilities
  • ▹ Need for periodic audits to maintain security posture

🎯 Hardening Objectives

Identify Weaknesses

Identify server configuration weaknesses through comprehensive security audit.

Increase Hardening Index

Increase Lynis Hardening Index from baseline ~55 to ≥ 80.

Strengthen Authentication

Strengthen authentication & remote access security.

Secure System

Secure kernel, network & file system configurations.

Documentation

Document the process for audit trail and compliance.

02 — About Lynis

Lynis is an open-source security auditing tool for Unix-based systems that performs system health scanning, vulnerability profiling, and compliance testing.

🛡️
Security Scanner
Checks system configuration against security best practices
📊
Hardening Index
Provides a 0–100 score as a measure of security level
✅
Compliance
Supports CIS Benchmark, ISO 27001, HIPAA, PCI-DSS

Lynis Scan Output Components

Code Meaning Action Required
WARNING High-risk finding Must be addressed immediately
SUGGESTION Improvement recommendation Recommended to fix
INFO Configuration information For reference only
OK Configuration is secure No action needed

04 — Phase 1: Preparation

Installing Lynis

1. System Update

root@srv-prod-01:~# apt update && apt upgrade -y root@srv-prod-01:~# apt install -y curl wget gnupg2 software-properties-common

2. Install Lynis via Package Manager

root@srv-prod-01:~# apt install -y lynis root@srv-prod-01:~# lynis --version # Output: Lynis 3.0.8

3. Backup & System Snapshot

root@srv-prod-01:~# cp /etc/lynis/default.prf /etc/lynis/custom.prf root@srv-prod-01:~# cp /etc/ssh/sshd_config /root/lynis-backup/sshd_config.before root@srv-prod-01:~# cp /etc/sysctl.conf /root/lynis-backup/sysctl.conf.before root@srv-prod-01:~# cp /etc/login.defs /root/lynis-backup/login.defs.before
️ Risk Mitigation: Ensure console access (not only SSH), prepare rollback plan, test in staging environment first, and keep an active SSH session open during changes.

05 — Phase 2: Execution — Initial Audit

Running Lynis Audit

System Audit Command

root@srv-prod-01:~# lynis audit system # For non-interactive mode: root@srv-prod-01:~# lynis audit system --quick --no-colors

Generate Full Report

root@srv-prod-01:~# lynis audit system --pentest --report-file /root/lynis-report-before.txt # Log output: /var/log/lynis.log # Report output: /var/log/lynis-report.dat

06 — Action Plans & Remediation

🔐 Action 1: SSH Hardening

Backup Configuration

root@srv-prod-01:~# cp /etc/ssh/sshd_config /root/lynis-backup/sshd_config.$(date +%F)

Configure /etc/ssh/sshd_config

# Disable root login & password auth PermitRootLogin no PasswordAuthentication no PermitEmptyPasswords no ChallengeResponseAuthentication no # Use key-based auth only PubkeyAuthentication yes AuthenticationMethods publickey # Restrict SSH users AllowUsers admin deployer # Change default port Port 2222 # Session & security LoginGraceTime 30 MaxAuthTries 3 ClientAliveInterval 300 ClientAliveCountMax 2 X11Forwarding no AllowTcpForwarding no

Restart Service

root@srv-prod-01:~# sshd -t # Test configuration root@srv-prod-01:~# systemctl restart ssh

🛡️ Action 2: Kernel & Network Hardening

Configure /etc/sysctl.conf

# Disable IP forwarding net.ipv4.ip_forward = 0 # Anti IP spoofing net.ipv4.conf.all.rp_filter = 1 net.ipv4.conf.default.rp_filter = 1 # Disable ICMP redirect net.ipv4.conf.all.accept_redirects = 0 net.ipv4.conf.default.accept_redirects = 0 # SYN flood protection net.ipv4.tcp_syncookies = 1 net.ipv4.tcp_max_syn_backlog = 2048 # Disable IPv6 net.ipv6.conf.all.disable_ipv6 = 1 net.ipv6.conf.default.disable_ipv6 = 1 # Log suspicious packets net.ipv4.conf.all.log_martians = 1

Apply Configuration

root@srv-prod-01:~# sysctl -p root@srv-prod-01:~# sysctl --system

🔑 Action 3: Password Policy

Configure /etc/login.defs

PASS_MAX_DAYS 90 PASS_MIN_DAYS 1 PASS_WARN_AGE 14 PASS_MIN_LEN 14 UMASK 027

Install & Configure libpam-pwquality

root@srv-prod-01:~# apt install -y libpam-pwquality # /etc/security/pwquality.conf minlen = 14 dcredit = -1 ucredit = -1 lcredit = -1 ocredit = -1 enforcing = 1

📁 Action 4: File Permissions & Firewall

Fix Critical File Permissions

root@srv-prod-01:~# chmod 644 /etc/passwd root@srv-prod-01:~# chmod 640 /etc/shadow root@srv-prod-01:~# chmod 600 /etc/gshadow root@srv-prod-01:~# chmod 700 /root

Configure UFW Firewall

root@srv-prod-01:~# ufw default deny incoming root@srv-prod-01:~# ufw default allow outgoing root@srv-prod-01:~# ufw allow 2222/tcp comment 'SSH-hardened' root@srv-prod-01:~# ufw allow 80/tcp comment 'HTTP' root@srv-prod-01:~# ufw allow 443/tcp comment 'HTTPS' root@srv-prod-01:~# ufw --force enable

08 — Conclusion & Lessons Learned

✅ Achievements

  • Hardening Index increased by 58% (55 → 87)
  • Warnings reduced from 18 → 3
  • SSH successfully hardened with key-based auth
  • Kernel parameters aligned with best practices
  • Firewall active with default deny policy
  • Password policy strengthened via PAM
  • Complete audit trail documentation

📝 Lessons Learned

  • Backup is mandatory — before any changes
  • Test SSH config in a separate session
  • Lynis provides a clear remediation roadmap
  • Hardening should be incremental, not all at once
  • Post-hardening monitoring is equally important
  • Document every change for audit purposes
